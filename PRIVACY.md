# Приватность spend-tracker

Коротко: по умолчанию приложение **не делает ни одного сетевого вызова** и не имеет телеметрии.
Данные (SQLite-файл; из исходников — `data/spend.db`, при установке одной командой — папка данных:
`%LOCALAPPDATA%\spendtrack` на Windows, `~/.local/share/spendtrack` на macOS/Linux; точный путь —
`spendtrack paths`) лежат только на вашей машине и не шифруются на уровне приложения.

## Что происходит без настройки (по умолчанию)

- HTTP-сервер слушает только `127.0.0.1` (localhost) — снаружи недоступен.
- LLM **выключен**: без ключей ни один провайдер не вызывается, сеть не трогается вообще.
  Неизвестные категоризатору операции уходят в очередь «Подтвердить» к человеку.
- Это проверяется тестом: `uv run pytest tests/test_offline.py` (сокеты за пределами localhost блокируются;
  импорт, дайджест, doctor и страницы работают офлайн).

## Что и когда уходит наружу (только если вы включили LLM)

LLM включается осознанно — одним из двух способов:

**Свой LLM (BYO) / Ollama — рекомендуемый.** Укажите свой OpenAI-совместимый сервер в `.env`:
`SPENDTRACK_LLM_BASE_URL` + `SPENDTRACK_LLM_MODEL` + `SPENDTRACK_LLM_API_KEY`; либо локальный Ollama —
`SPENDTRACK_LLM_PROVIDER=ollama` (+ `SPENDTRACK_LLM_MODEL`, по умолчанию `qwen2.5-coder:3b`). Тогда данные
уходят только на указанный вами сервер, а при Ollama — не покидают машину вовсе. Автоматических фолбэков
в чужие сервисы в этом режиме нет.

**Free-каналы — осознанный opt-in.** Здесь каждый ключ включается сам за себя:
- `SPENDTRACK_OPENROUTER_API_KEY` — канал OpenRouter (`https://openrouter.ai/api/v1`, чужой сервер):
  данные уходят туда;
- `SPENDTRACK_FREEL_LLM_API_KEY` сам по себе не включает ничего — это лишь ключ для совместимого
  локального прокси, если вы его сами подняли;
- локальный прокси участвует только при явном `SPENDTRACK_ALLOW_LOCAL_LLM=1` (и сам проксирует данные
  в чужой сервис — ключ сам по себе согласием на шлюз не считается).
Для обычного использования поднимать ничего не нужно.

В обоих случаях для операций, которые не закрыты правилами, отправляется:

- описание операции (усечено до 300 символов; сюда же попадает название магазина, если банк его передаёт — до 80 символов),
- сумма,
- до 8 few-shot примеров из ваших правок (описание, сумма, категория) — они помогают модели.

Дата и счёт (даже в виде псевдонима `acc_xxxx`) не отправляются вовсе — для классификации они не нужны.

Проверить текущий режим (без сети и без показа ключей): `uv run spendtrack llm-status`.
Ответ модели валидируется: категория вне таксономии отвергается, и строка уходит в очередь на
подтверждение. Это ограничивает, но не исключает вред от инъекции в описании операции: существующая,
но неверная категория может пройти с высокой уверенностью — правку всегда можно внести в очереди
«Подтвердить».

## Как выключить / проверить

- Выключить: удалите из окружения/`.env` все LLM-переменные — `SPENDTRACK_LLM_PROVIDER`,
  `SPENDTRACK_LLM_BASE_URL`, `SPENDTRACK_LLM_MODEL`, `SPENDTRACK_LLM_API_KEY`,
  `SPENDTRACK_OPENROUTER_API_KEY`, `SPENDTRACK_FREEL_LLM_API_KEY`, `SPENDTRACK_ALLOW_LOCAL_LLM` —
  LLM-вызовы прекратятся, правила и офлайн-кэш продолжат работать. Остальные `SPENDTRACK_*`
  (пути к базе/данным) трогать не нужно.
- Проверить отсутствие утечек: `uv run pytest tests/test_offline.py` (в CI — всегда).
- Бэкапы (`spendtrack backup`, VACUUM INTO) локальные; копию желательно хранить вне ноутбука —
  `--copy-to <USB/другая папка>` (внешний диск или папка вашего облака; приложение само никуда не отправляет).

## Метрики без телеметрии (opt-in, вручную)

Приложение **не отправляет статистику** — ни при запуске, ни при импорте, ни «раз в день». Чтобы автор мог
понимать, что продуктом пользуются, есть добровольная анонимная сводка:

```
uv run spendtrack doctor --share
```

Команда только **печатает** сводку и ссылку с предзаполненным issue — ничего не отправляется, пока вы сами
не скопируете текст или не откроете ссылку (это ваш выбор и ваш клик). **Issue на GitHub публичный**: если
отправите — текст увидят все; лишнее можно удалить перед отправкой. Без `--share` команда `doctor`
работает как раньше.

Что входит в сводку:

- версия spendtrack, версия схемы, версия Python, ОС (windows/macos/linux) и режим запуска (repo/installed);
- режим LLM: off/byo/ollama/free (без ключей и адресов);
- числа: транзакций всего и из импорта, партий импорта, задействованных категорий из общего числа,
  keyword-правил, бюджетов, строк в очереди;
- история в грубых бакетах (≤30 / 31–90 / 91–365 / >365 дней);
- наличие локального бэкапа и внешней копии (да/нет).

Чего в сводке нет и не будет: суммы, балансы, описания, мерчанты, счета, названия категорий по отдельности,
точные даты, пути к файлам, ключи и адреса LLM.

## Чего приложение не делает

- Не отправляет телеметрию/аналитику, не проверяет обновления по сети, не «звонит домой».
- Не хранит сырые номера карт (только псевдонимы `acc_xxxx`).
- Не шифрует БД — если нужна защита файла, используйте BitLocker/права доступа ОС.
