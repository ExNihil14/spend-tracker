# Верификация spend-tracker (fresh-context прогон)

Задокументированный DoD-шаг (субагент-verifier — позже). Критерий: каждый сценарий подтверждён **живым поведением нового кода**, а не кодом ответа 200.

## Прогон
1. **Сценарий.** Из `git diff` выпиши изменённый пользовательский сценарий + 2 соседних потока (что могло сломаться рядом). Три сценария — три пункта отчёта.
2. **Стенд.** Python-правки — `nssm restart spendtrack` (прод 8766); либо temp-стенд через `start-detached.ps1` (`uv run uvicorn spendtrack.main:app --port 8799` с `SPENDTRACK_DB_PATH`). Jinja-шаблоны применяются без рестарта; демо-данные — `scripts/demo_data.py seed`, стенд 8767.
3. **Факты.** По каждому сценарию: команда или URL + наблюдаемый ответ/скрин; `/health` и `/health/data`; в логах ошибок нет.
4. **Отчёт без правок.** Код в ходе прогона не менять; вердикт по каждому сценарию (пройден/нет + чем доказан); находки — в ревью/continue; одноразовые тестовые записи удалить.

## Gotchas
- e2e поднимает собственный uvicorn на tmp-порту и tmp-БД — полезно, но live-прогон не заменяет.
- Убивать **слушающий** PID (`Get-NetTCPConnection -LocalPort 8766 -State Listen`), а не `uv`-родителя; запуск — только `start-detached.ps1`, не `&`/`Start-Process`.
- Не чейнить sleep/поллинг в команду запуска — опрос отдельными короткими командами.
- Playwright — реальный браузер без изоляции: открывать только localhost-стенды проекта.
- Прод-БД не засорять: тестовые записи — на temp-БД (`SPENDTRACK_DB_PATH`), иначе удалить после.
